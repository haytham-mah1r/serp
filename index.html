Builds a Google search URL with the uule, hl, and gl parameters, so results render as if the search came from another city or country. Everything runs in your browser — nothing is sent anywhere but Google.

If results keep showing your real location: that's almost never the uule value being wrong — it's Google reading your actual GPS/IP because it trusts that signal more.
  1. Block location access for google.com at chrome://settings/content/location
  2. Test in a fresh incognito window, signed out of any Google account
  3. For the first test, avoid literal "near me" — try "in <city>" instead, which respects uule more reliably

How it works: the canonical name is packed into a small protocol-buffer (fields for a version marker, a producer id, and the location string), then base64-encoded into the uule value Google reads. This is the same mechanism Google Ads uses for geo-targeted campaigns, and the same one valentin.app and similar public tools use — it's a documented URL parameter, not a bypass of anything.

Chrome DevTools has a native "Sensors" location override if you'd rather change location at the browser level.
